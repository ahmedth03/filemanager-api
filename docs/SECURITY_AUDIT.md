## OWASP API Top 10 Assessment

### API1 — Broken Object Level Authorization
**Status: PASS**
- All resource-access endpoints verify ownership: `listing.ownerId !== userId` → 403
- Chat messages check room membership before allowing access
- Admin routes protected by `@Roles(Role.ADMIN)` + `RolesGuard`
- ✅ No BOLA vulnerabilities found

### API2 — Broken Authentication
**Status: PASS with recommendations**
- ✅ Passwords hashed with bcrypt cost factor 12
- ✅ JWT access tokens expire in 15 minutes
- ✅ Refresh token rotation: old session deleted on refresh
- ✅ Sessions stored in DB (`UserSession`); logout deletes session
- ⚠️ **MEDIUM**: JWT secrets have weak fallback values (`'fallback-secret'`) — production MUST override via environment variables. Add startup check:
```typescript
if (jwtSecret === 'fallback-secret') throw new Error('JWT_SECRET must be set in production');
```
- ⚠️ **LOW**: No account lockout after N failed login attempts (rate limiting provides partial mitigation)

### API3 — Broken Object Property Level Authorization
**Status: PASS**
- `ValidationPipe` with `whitelist: true` + `forbidNonWhitelisted: true` strips and rejects unknown properties
- DTO classes explicitly define allowed fields — no mass assignment vulnerabilities

### API4 — Unrestricted Resource Consumption
**Status: PASS with recommendations**
- ✅ ThrottlerModule: 10 req/1s, 50 req/10s, 200 req/60s (global)
- ✅ File upload limit: 10 MB per file, 10 files per request
- ✅ Max 20 images per listing
- ✅ Pagination enforced on all list endpoints
- ⚠️ **MEDIUM**: Auth endpoints (`/login`, `/register`, `/forgot-password`) should have stricter rate limits than global defaults. Recommend `@Throttle({ short: { limit: 3, ttl: 60000 } })` on login endpoint.

### API5 — Broken Function Level Authorization
**Status: PASS**
- Admin routes grouped under `/api/v1/admin` and guarded by `@Roles(Role.ADMIN)`
- Specialty CRUD (create/update) requires ADMIN role
- User status update requires ADMIN role
- ✅ No function-level authorization bypasses found

### API6 — Unrestricted Access to Sensitive Business Flows
**Status: PASS**
- Craftsman creation limited: one profile per user (409 Conflict on duplicate)
- Review creation: checked for prior review before allowing
- Reports: users can submit but not self-resolve
- ✅ Business flow restrictions properly enforced

### API7 — Server-Side Request Forgery (SSRF)
**Status: N/A**
- Application does not make server-side HTTP requests to user-supplied URLs
- Cloudinary URLs are generated by SDK, not user-supplied
- ✅ No SSRF surface area

### API8 — Security Misconfiguration
**Status: PASS with recommendations**
- ✅ Helmet enabled with default security headers
- ✅ CORS restricted to `*.harfidar.dz` in production
- ✅ Swagger UI disabled when `NODE_ENV=production`
- ✅ Global exception filter prevents stack trace leakage
- ⚠️ **HIGH**: Default admin credentials (`admin@harfidar.dz` / `Admin@123456`) must be changed before launch. Add runtime check or seed with a randomly generated password.
- ⚠️ **LOW**: `pgAdmin` exposed on port 5050 in Docker Compose — must NOT be included in production deployment

### API9 — Improper Inventory Management
**Status: PASS**
- Single API version (`v1`), versioning scheme in place for future
- No legacy/shadow endpoints found
- Swagger documents all endpoints when enabled

### API10 — Unsafe Consumption of APIs
**Status: PASS**
- Cloudinary SDK handles all external API calls
- Firebase Admin SDK handles FCM
- Nodemailer handles SMTP
- ✅ No unsafe direct HTTP calls to external APIs

## Data Protection

### Sensitive Data Handling

| Data Type | Storage | Encryption | Exposure Risk |
|-----------|---------|-----------|---------------|
| Passwords | DB (passwordHash) | bcrypt(12) | None — hash only |
| JWT access tokens | Client memory | JWT signed | Expires in 15m |
| JWT refresh tokens | DB (UserSession) | Signed JWT | 7-day expiry |
| Phone numbers | DB plaintext | None | ⚠️ Medium |
| Email addresses | DB plaintext | None | Low |
| Profile images | Cloudinary CDN | TLS in transit | Low |

- ⚠️ **MEDIUM**: Phone numbers stored in plaintext. Consider encrypting at rest for GDPR/Algerian data protection compliance.
- ⚠️ **LOW**: Email addresses in plaintext — acceptable for functional purposes but document in privacy policy.
- ✅ No credit card or payment data stored (no payment gateway — by design)
- ✅ `passwordHash` never returned in API responses (explicit `select` excludes it)

### Transport Security

- ✅ HTTPS enforced via nginx TLS termination
- ✅ Strict-Transport-Security header via Helmet
- ✅ WebSocket connections via `wss://` in production

## Input Validation

- ✅ All DTOs use `class-validator` decorators
- ✅ `@IsEnum(WilayaCode)` prevents invalid wilaya codes
- ✅ `@MaxLength()` on all string fields prevents oversized inputs
- ✅ `@Min(0)` on price fields prevents negative values
- ✅ File type validation on uploads (image/* only via multer)
- ⚠️ **LOW**: Chat message content allows arbitrary Unicode — consider adding profanity/spam filter for Arabic text in a future release
- ⚠️ **LOW**: Report `reason` field is free-text with MaxLength — adequate for now

---

## Infrastructure Security

- ✅ Docker images use Alpine base (minimal attack surface)
- ✅ Non-root user in production Dockerfile recommended
- ⚠️ **MEDIUM**: PostgreSQL port 5432 and Redis port 6379 should NOT be exposed on the host in production (bind to `127.0.0.1` only or use Docker network)
- ⚠️ **MEDIUM**: No secrets manager integration — secrets in `.env` file on server. Recommend AWS Secrets Manager, HashiCorp Vault, or Docker Secrets for production.
- ⚠️ **LOW**: Docker socket not mounted (good — avoids container escape)

---

## Mobile Security (Flutter)

- ✅ `flutter_secure_storage` used for JWT token storage (Keychain/Keystore — not SharedPreferences)
- ✅ Certificate pinning: NOT implemented — **recommend adding** for production (use `http_certificate_pinning` package)
- ⚠️ **MEDIUM**: No jailbreak/root detection — add `flutter_jailbreak_detection` before iOS/Android release
- ⚠️ **LOW**: Sensitive data (phone numbers) visible in chat — ensure device screenshot protection in sensitive screens
- ⚠️ **LOW**: Deep-link handling via GoRouter — verify all deep link parameters are validated before use

## Pre-Launch Security Checklist

### Must fix before launch (High severity)
- [ ] Change default admin credentials (`ADMIN_EMAIL`, `ADMIN_PASSWORD`)
- [ ] Ensure JWT secrets are ≥ 64 chars in production environment

### Should fix before launch (Medium severity)
- [ ] Add stricter rate limits on `/auth/login`, `/auth/register`, `/auth/forgot-password`
- [ ] Add startup assertion: fail fast if JWT secrets equal fallback values
- [ ] Bind PostgreSQL and Redis to internal Docker network only (no host port exposure)
- [ ] Use secrets manager instead of `.env` file for production secrets

### Acceptable for v1.0 launch (Low severity — schedule for v1.1)
- [ ] Account lockout after N failed login attempts
- [ ] Certificate pinning in Flutter app
- [ ] Jailbreak/root detection
- [ ] Phone number encryption at rest
- [ ] Arabic text moderation for chat/reviews
